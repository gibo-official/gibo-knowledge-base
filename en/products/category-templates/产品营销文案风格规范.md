## I. Document Positioning & Scope of Application

### 1.1 What This Is

A set of **technical B2B marketing copy / solution-oriented product manuals**, essentially **sales-enablement documents** — used by sales engineers, design institutes, engineering contractors, and distributors to persuade the client (project owner), support bidding, and enable training. They are not end-consumer advertising.

### 1.2 Where It Fits ✅

| Scenario | Fit | Notes |
|------|:----:|------|
| Project bidding / technical bid-document annex | ★★★★★ | Full parameters, compliant with execution standards, with ROI — the favorite of bid-evaluation experts |
| Design institute / client selection catalog | ★★★★★ | Technical-positioning table + specification-parameter table, easy to include in design atlases |
| Distributor / agent training | ★★★★☆ | The "golden-line + benefit" selling points can be used directly as sales scripts |
| Source content for official-website product detail pages | ★★★★☆ | Requires image breakdown and product photos, but the skeleton is ready-made |
| Trade-show sample catalog / brochure copy | ★★★★☆ | Can be bound into a catalog once paired with visuals |
| Sales reference book / bid-script library | ★★★★★ | The six-section structure is naturally suited to "one-page selling-point cards" |

### 1.3 Where It Does NOT Fit ❌

- B2C consumer advertising / Xiaohongshu / Douyin scripts (too long and too technical)
- E-commerce detail pages (JD.com / Tmall — require more images, shorter sentences, more emotional tone)
- Overseas social media / English website (requires translation + localization, and European/American buyers trust third-party certifications more)
- Technical white paper / academic paper (heavy marketing tone, not academically neutral enough)

## II. Six-Section Standard Structure (Mandatory)

Each piece of copy must contain the following six top-level sections + appendix, in fixed order:

```
I. Product Introduction
II. Functional Features
III. Core Selling Points
IV. Specifications & Performance Parameters
V. Installation Instructions
VI. Application Scenarios
Appendix (A. Core Technology Index / B. Product Certifications & Qualifications / C. Contact Information)
```

### 2.1 I. Product Introduction (Single-paragraph narrative + 3 subsections)

**The opening is a coherent narrative; do not split it into 1.1~1.4 subheadings.** In one go it must clearly cover four things: what this product does → where it is used → what technology makes it stand out → what real value it delivers to the user. Blend these four into 2–4 naturally connected paragraphs of prose, with no subheadings and no bullets.

| Subsection | Requirement |
|------|------|
| (Opening narrative) | No subheading; blend the four elements "function → scenario → technology → value"; bold the product's full name on first appearance |
| 1.1 Technical Positioning | **Must be a comparison table** (generation / principle / mode / power consumption / GIBO representative product), placing the product in a technology-evolution coordinate system |
| 1.2 Key Metrics | 3–6 `-` bullets listing the hardest numbers (precision / power consumption / lifespan / protection / flow rate …); the heading was once "A Few Key Figures," now uniformly renamed "Key Metrics" |
| (No 1.3) | The "About GIBO" brand endorsement is **not** placed in the body; it is uniformly moved to the opening paragraph of Appendix B. Certifications & Qualifications at the end of the document |

### 2.2 II. Functional Features (Recommended 5–7 items)

- Each item uses `### 2.x Feature Name —— Subtitle` (separated by em dash)
- Technical principles are broken down with bullets (sensing unit / processing unit / main control unit …)
- Key performance is presented in **inline tables** (test item / condition / result)

### 2.3 III. Core Selling Points (Fixed at 3 items)

Each selling point follows a fixed pattern:

```
### Selling Point N: Short Title —— One Value Proposition

> **Golden-line Quote** (bold, highlighting the customer's pain point or philosophy)

[Principle / mechanism explanation, 1–2 paragraphs]

**Actual Benefit**: [Quantified ROI — how much water / labor hours / cost saved, with a specific calculation scenario]
```

- "Actual Benefit" must be **quantified** (number + unit + calculation premise); no empty talk
- The 3 selling points should cover three angles: technical differentiation / cost (power consumption / maintenance) or water-saving experience / reliability or engineering convenience; pick the three hardest-hitting points, do not pad

### 2.4 IV. Specifications & Performance Parameters (Tabular, 5–7 groups)

- Electrical parameters / water-circuit parameters / sensing parameters / operating environment / mechanical & protection / lifespan & reliability / execution standards
- All in Markdown tables, with parameter on the left and specification on the right
- Execution standards must list real standard numbers such as CJ/T 194-2014

### 2.5 V. Installation Instructions

- 5.1 Pre-installation Inspection (bullet checklist)
- 5.2 Installation Notes (`⚠️` marks key warnings)
- 5.3 Installation Steps (numbered ordered list)
- 5.4 Power-on Self-check Notes
- 5.5 Battery Replacement (if applicable)

### 2.6 VI. Application Scenarios

- Segmented by industry (shopping mall / office building / transportation hub / hotel / hospital / school …), each scenario includes:
  - **Typical Needs**: the pain points of clients in that industry
  - **[Product] Solution Advantage**: how this product resolves them one by one (corresponding to the selling points above)
- For finished end products write "Application Scenarios"; **for component-level products rewrite as "Applicable End Products & Integration Solutions"** (see §IV)

### 2.7 Appendix (Three fixed sections)

- A. GIBO Core Technology Index Table (number / technology name / application in this product) — numbering references the 18-item index in `zh/technology/core-technologies.md`
- B. Certifications & Qualifications: the opening first paragraph is the "About GIBO" brand endorsement (20 years / contributing drafter (drafting unit) of GB/T 41863-2022 and T/XMBK 002-2024 / National High-tech Enterprise / Specialized & Sophisticated SME / Boiling Quality Gold Award, etc.), followed by listing the actual certification numbers (CE / cUPC / NSF / WRAS / WaterMark / ISO three-system)
- C. Contact Information (company / Chinese & English websites / hotline / email / address)

## III. Writing Conventions (Mandatory)

1. **Core Technology Reference**: When GIBO technology is mentioned in features / selling points, mark `(Core Technology #N)` and build an index table in Appendix A.
2. **Quantified Benefit**: All "Actual Benefit" entries must carry numbers; the calculation baseline (e.g., "50 hand-washing stations") must be consistent throughout the document for cross-comparison.
3. **Golden-line Quote**: Core selling points use a `>` blockquote to carry the pain-point golden line, in bold.
4. **Tables First**: Parameters, comparisons, and test results are always in tables, never prose lists.
5. **Above-the-fold Positioning**: The `>` blockquote at the top of the document states version / date / product positioning in one sentence.
6. **Emoji Usage**: Use emoji as visual anchors in highlight overviews (🔋💧🛡️ etc.); do not use emoji in body text.
7. **Disclaimer**: A fixed disclaimer + copyright at the end, noting the source specification's revision and date.

---

## IV. Special Handling for Component-level Products

When the product is a **component / module** (such as a control box, sensor module) rather than a finished end product:

- Change the title of Section VI to **"Applicable End Products & Integration Solutions,"** with content covering the matching end products and ODM integration value
- Clearly mark the synergy of "paired with XX end product / module," and do not claim end-product metrics as its own
- Installation instructions focus on "key points for pairing with the end product," and may be briefer
- Brand strength and the core-technology index are still retained (reflecting platform capability)

## V. Quality Scoring Criteria (Out of 100)

| Dimension | Weight | Scoring Points |
|------|:----:|---------|
| Content Completeness | 15 | Whether the six sections + appendix are complete, whether subsections are missing |
| Technical Accuracy | 15 | Whether parameters are sourced from the spec, whether any are fabricated |
| Marketing Persuasiveness | 15 | Whether selling points hit pain points, whether "Actual Benefit" is quantified |
| Structural Clarity | 15 | Whether the six-section structure is standardized, whether the table hierarchy is clear |
| Data / Argument Support | 15 | Whether there are real numbers, standard numbers, ROI calculations |
| Scenario Differentiation | 12 | Whether application scenarios are segmented by industry and differentiated |
| Readability / Fluency | 13 | Whether golden lines, emoji, and tables improve readability, whether there are ill-formed sentences |

## VI. Red Zones / Taboos

1. ❌ **Circular phrasing**: e.g., "Moisture-resistant: adapts to high-humidity environments (see … parameters)" — says nothing. If the source spec has errors (e.g., the 9168 moisture-resistance entry was recorded as a low-temperature test), verify, correct, and mark; do not copy verbatim.
2. ❌ **Fabricated parameters**: Data not present in the spec must not be invented; if standard test conditions genuinely need supplementing (e.g., moisture test 40±2℃/95%RH/48h), the basis must be noted and marked.
3. ❌ **Claiming end-product metrics as the component's own**: In component copy, metrics marked as "paired with faucet sensor module" must not be written as its own independent metrics.
4. ❌ **Empty selling-point talk**: Prohibit numberless expressions such as "excellent quality" / "superior performance."
5. ❌ **Wrong core-technology number reference**: `#N` must match the index in `core-technologies.md`.

## VII. Pre-publication QA Checklist

- [ ] Six sections + appendix complete, correct order
- [ ] Technical positioning is a comparison table, product is in the coordinate system
- [ ] All 3 selling points have "golden line + quantified benefit"
- [ ] All spec parameters tabular, including execution-standard numbers
- [ ] Core-technology `#N` references match Appendix A and numbering is correct
- [ ] Application scenarios differentiated by industry (end products) / integration solutions (components)
- [ ] No circular phrasing, no fabricated parameters, no verbatim copy of source-file typos
- [ ] Calculation baseline consistent throughout the document
- [ ] Disclaimer + copyright + source-spec revision complete
- [ ] No residual Chinese punctuation or word-clumping in the whole text
